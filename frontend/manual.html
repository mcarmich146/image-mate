Image-Mate · User Manual

Archive, analytics, and monitoring workbench

Image-Mate is a local-first geospatial workbench for browsing Sentinel-2 and Satellogic imagery, reviewing image products, running local analytics, preparing mosaics, and monitoring regions for new archive captures.

Start here

Run Image-Mate locally, open the displayed address in a browser, and use the five workspaces in the left panel. The map is the shared workspace: search areas, drawn polygons, selected imagery, detections, and mosaic regions are shown there. Technical utilities, schedules, run logs, settings, and this manual are in the top-right Tools drawer.

Local-first processing: archive search and provider downloads use the configured APIs, while aircraft inference and host-side mosaic processing run on the computer where Image-Mate is running. Keep the local service on a trusted network when credentials are configured.

Explore the archive

  1. Pan or zoom the map to the area of interest, or draw a rectangle from the map drawing controls.
  2. Choose the source and collection in Archive Search. Satellogic and Sentinel-2 may be enabled independently from Layer Controls.
  3. Set the date range and optional cloud, GSD, satellite, and sensor-generation filters, then choose Search View Extent.
  4. Use the carousel on the right to inspect results. Select the checkbox on each image to reveal the contextual selection bar for comparison, animation, analysis, mosaicking, download, and more.
  5. Right-click the map to task a point or area, start a Monitoring Project, create a mosaic from selected imagery, or copy coordinates. Mosaic stays disabled until at least two images are selected.
  6. Use the ⌖ button beside the location search to save the current map center and zoom as the default view for the next session.

NewSat sensor generations

Satellogic imagery can be filtered and labeled as NewSat Mark IV or NewSat Mark V. These generations have different native and L1D-SR resolutions. Keep the generation filter consistent when comparing products or preparing a mosaic.

Preview behavior

Image-Mate uses server-side preview and tile proxies. This keeps provider credentials and signed URLs out of browser links. A preview may be unavailable when a product has no thumbnail asset, the provider token has expired, or the selected collection is not enabled.

Mosaic Workbench

Mosaicking is a durable project workbench because it needs source selection, processing status, completion monitoring, and quality control without crowding normal archive browsing.

Create a mosaic

  1. Filter the carousel to the captures and sensor generation you want to use. QuickView is suitable for discovery and selection, but never becomes a mosaic raster.
  2. Select two or more overlapping images with the checkbox on each carousel card.
  3. Choose Mosaic above the carousel. Select Mosaic whole strips for complete source footprints, or Draw polygon for mosaic to limit processing to a smaller region.
  4. Choose Mark IV, Mark V, or mixed inputs. Select RGB, or RGB-NIR only when every source exposes compatible NIR data. Image-Mate defaults to the coarsest native input resolution; a finer upsampled output is rejected in v1.
  5. Press Generate. Image-Mate resolves every selected capture to L1D-SR Visual tiles. If coverage is missing, confirm the provider processing request. The saved project remains in Awaiting L1D-SR while Image-Mate checks the archive periodically.
  6. When every capture has complete L1D-SR coverage, Image-Mate replaces the discovery inputs with the high-resolution tile set and starts the local host worker automatically. Processing moves through queued, downloading, processing, color balancing, seam optimization, and QC Required before finalization.
  7. Review progress in the Mosaic tab. Choose automatic acceleration, Apple MPS, CUDA, OpenCL, or CPU in the popup. If worker startup fails, press Start Processing in the Mosaic workbench.
L1D-SR requirement: mosaics always use L1D-SR Visual products. Provider processing requests can consume contract entitlement and therefore require an explicit confirmation. The default listener checks every five minutes and survives application restarts.
Overlap requirement: selected scenes should form one connected overlap group. Separate groups cannot be aligned into one reliable mosaic.

Cloud edit / repair

After a mosaic is generated, select it in the Mosaic tab and choose Edit cloud area. Draw a polygon around the cloud. Image-Mate searches for the nearest recent covering image, inserts the replacement area, and rebalances the result. Use small repair polygons first; this reduces download and processing time.

The intended output is color balanced with softened seams. The worker records source boundaries, seam metadata, and repair history so the result can be reviewed or reproduced. If no compatible L1D-SR replacement exists, the repair becomes an approval-required product-generation action.

Aircraft analytics and Model Lab

The Analyze workflow is designed for iterative analyst-in-the-loop refinement. It combines provider analytics, local inference, versioned Analysis Recipes, Results, and Model Lab. It can run on Satellogic L1B Visual and L1D-SR Visual imagery where the corresponding asset is available; compatibility is checked before execution.

Run a detector

  1. Search for a suitable area and choose an image from the carousel.
  2. Open Analyze → Run Analysis or Analyze → Model Lab, choose the image/product and compatible model, and run detection.
  3. Review detections on the map and inspect the image chips. Confidence is a review aid, not a final intelligence judgment.

Validate and add classes

Use the validation controls to mark a detection as aircraft, helicopter, or none/background. Draw a polygon over a missed object to create a new annotation. Training metadata should record the source item, product, tile bounds, class, confidence, and analyst note.

New subclasses such as jet fighter should be introduced as an explicit dataset/model version rather than silently changing an existing class map. Keep a representative mix of positive, negative, and edge-case chips.

LLM-assisted review

When the Luna evaluator is configured, a refinement run can send selected chips, context, and confirmed examples for a second opinion. Treat the evaluator as an assistant: the analyst remains responsible for accepting, rejecting, or correcting labels before a dataset is used for training.

Model artifacts

Model Lab saves source tiles with analyst labels, builds scene-separated YOLO-OBB bundles, starts host-side fine-tuning/evaluation jobs, and lets you activate a model only after a held-out evaluation succeeds. Set IMAGE_MATE_AIRCRAFT_TRAINING_PYTHON to a host Python environment containing ultralytics and PyTorch/MPS or CUDA; the service never overwrites the active model automatically.

Archive watches and email alerts

A Monitoring Project is the durable analyst-facing object for a polygon, archive sources, cadence, quality filters, an Analysis Recipe, alert policy, and follow-on actions. Existing archive watches and recollection monitors remain compatible underneath it.

Create a watch

  1. Open Monitor and use the project setup controls. Choose the AOI, source/collection, and compatible recipe.
  2. Enable automatic email/workflow actions if desired. NewSat tasking and product-generation actions are always placed in the Proposed Actions approval queue.
  3. Press Create from current AOI, then use Check selected to run an immediate archive check.

Each check uses a small overlap window to account for provider indexing delay. Seen item identities are deduplicated in SQLite, so the same capture is not repeatedly emailed. If email delivery fails, items remain pending and can be delivered after SMTP configuration is corrected.

Email configuration

Set these values in the project .env file:

IMAGE_MATE_ALERT_EMAIL_TO=analyst@example.org
IMAGE_MATE_PUBLIC_BASE_URL=http://your-host:8000
IMAGE_MATE_SMTP_HOST=smtp.example.org
IMAGE_MATE_SMTP_PORT=587
IMAGE_MATE_SMTP_USERNAME=analyst@example.org
IMAGE_MATE_SMTP_PASSWORD=use-a-secret-store-or-local-env
IMAGE_MATE_SMTP_FROM=analyst@example.org
IMAGE_MATE_SMTP_USE_TLS=true
IMAGE_MATE_SMTP_USE_SSL=false
IMAGE_MATE_ARCHIVE_WATCH_ENABLED=true
IMAGE_MATE_ARCHIVE_WATCH_INTERVAL_SECONDS=300
Important: IMAGE_MATE_PUBLIC_BASE_URL must be reachable by the person opening the email. A localhost URL works only on the same computer running Image-Mate.

Messages contain Image-Mate preview-proxy links based on item identity. They do not include provider-signed URLs or archive credentials.

Tasking, schedules, and subscriptions

Tasking uses one composer for point, area, and grid planning. The secondary tabs separate Proposed, Upcoming, Active, History, and Plan New. A task can reference an Analysis Recipe and Monitoring Project; delivered imagery can then become project evidence or Analyze results.

Schedules, POI sets, subscriptions, technical workflow graphs, and run logs remain available from the Tools drawer. Task submission and product generation always retain explicit confirmation or approval protections.

API and integrations

The local API is the integration boundary for Hermes, Telegram-driven workflows, scripts, and standalone users. Interactive API documentation is available at /docs while the service is running.

POST /api/archive-watchesCreate a durable polygon watch.

GET/POST/PATCH /api/monitoring/projectsCreate and manage durable Monitoring Projects.
GET /api/monitoring/projects/{id}/alertsList deduplicated project alerts.
POST /api/alerts/{id}/dispositionSet New, Acknowledged, Dismissed, Escalated, or Actioned.
GET /api/proposed-actionsReview approval-required tasking and product-generation actions.
POST /api/proposed-actions/{id}/approve|rejectApprove or reject a proposed operational action.
GET/POST/PATCH /api/mosaics/projectsManage durable mosaic projects and their QC lifecycle.

Hermes can call these endpoints or invoke the project’s CLI wrappers. The UI, API, and CLI share the same local output and SQLite state, so a workflow can be started in one surface and reviewed in another.

Configuration checklist

  • Satellogic credentials and contract: SATELLOGIC_*.
  • Sentinel-2/CDSE access: MERLIN_S2_ENABLED and CDSE_*.
  • Aircraft model and provider: IMAGE_MATE_AIRCRAFT_MODEL and IMAGE_MATE_AIRCRAFT_PROVIDER.
  • Output, monitoring, and training directories: IMAGE_MATE_AIRCRAFT_LAB_DIR, IMAGE_MATE_AIRCRAFT_TRAINING_DIR, and the project output directory.
  • Mosaics: IMAGE_MATE_MOSAIC_WORKER_ENABLED, IMAGE_MATE_MOSAIC_ACCELERATOR, IMAGE_MATE_MOSAIC_PRODUCT_POLL_SECONDS, and optional backend/requirements-mosaic-gpu.txt for MPS/CUDA support.
  • Email and polling: the archive-watch variables above.

Never commit .env, provider tokens, SMTP passwords, downloaded imagery, model weights, or generated output databases. Use the project’s ignore rules and a secret manager for shared deployments.

Troubleshooting

SymptomCheck
No archive resultsConfirm the map viewport, date range, source credentials, collection, and cloud/GSD filters. Inspect /docs or the server log for the provider error.
Preview unavailableTry the correct product collection and confirm the provider token/contract. Some products expose only a visual asset, not a thumbnail.
Aircraft detector unavailableConfirm the model file exists, the local runtime is installed, and the configured provider is supported by the laptop.
Mosaic stays queuedConfirm the host worker is running, selected images overlap, and the AOI is small enough for the configured output limits.
Watch finds items but no email arrivesCheck IMAGE_MATE_ALERT_EMAIL_TO, SMTP host/port/from settings, TLS mode, and whether IMAGE_MATE_PUBLIC_BASE_URL is reachable. Pending items are retained for a later successful delivery.
Manual link is missingRestart the local service after updating the frontend, then open /manual.html directly.
